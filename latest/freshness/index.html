    Freshness¶

    [freshness] fails a workspace that locks packages that are years old, far behind their newest release, or no longer maintained:

    [freshness]
max-build-age-days = 730   # a build older than two years fails
max-majors-behind = 1      # a package two or more major versions behind its channel's newest fails
archived = true            # a conda-forge package whose feedstock is archived fails (on once the table exists)
pypi = true                # PyPI packages are checked too (on once the table exists)

    error[freshness.majors-behind] setuptools 59.8.0: 25 major versions behind 84.0.0, the newest in conda-forge, more than max-majors-behind (1)
  --> pixi.lock: environment "default", linux-64
  = help: upgrade it, or waive it while the upgrade is planned

    The keys are in the reference, the rules in the rule catalog. PyPI packages are checked against pypi.org; see PyPI packages.

    Build age¶

    max-build-age-days reads the build time each conda package's record in pixi.lock states, so it needs no network. A package whose record has no build time is reported as freshness.unknown.

    Major versions behind¶

    max-majors-behind compares a package's major version, its leading number, with the newest release in the repodata of the channel pixi.lock installs it from: conda.anaconda.org, prefix.dev or a mirror, whichever the lockfile names. A mirror is therefore judged by its own contents, and a mirror that lags upstream does not fail a workspace for releases it cannot install yet.

    • The package's own subdir and noarch both count, since packages move between them: setuptools' linux-64 builds stop at 65, and its newer releases are noarch.
    • Prereleases do not count as the newest release.
    • A calendar-versioned package (2024.8.30) is compared by its year.
    • A package its channel's repodata does not list, or whose major version cannot be read, is freshness.unknown.

    Repodata is read sharded where the channel serves it (CEP-16, as pixi does): a small index, then one shard per package. A channel that serves no shards is read whole, from repodata.json.zst or repodata.json, which for a large channel is a download of tens of megabytes the first time each day. No repodata is fetched unless max-majors-behind is set.

    Archived feedstocks¶

    archived asks whether conda-forge has archived the feedstock that builds a conda-forge package: archived feedstocks get no new builds, so no fixes either. It reads two files the conda-forge bot publishes:

    • all_feedstocks.json from regro/cf-graph-countyfair, listing active and archived feedstocks;
    • feedstock-outputs.json from conda-forge/feedstock-outputs, naming the feedstocks that build each package.

    The list can trail GitHub

    The archived list is the bot's, regenerated from the conda-forge GitHub organization on each bot cycle, so a feedstock archived on GitHub shows up a few hours later, and a cached copy adds up to a day more. A feedstock unarchived on GitHub likewise keeps failing until the list and the cache catch up.

    A package more than one feedstock builds counts as archived only when all of them are, since the lockfile does not say which one built it (libzlib comes from zlib or zlib-ng). A package no feedstock is known to build is freshness.unknown. Packages from other channels are not checked.

    PyPI packages¶

    With pypi (on once the table exists), max-build-age-days and max-majors-behind apply to PyPI packages from pypi.org too, from PyPI's JSON API, one request per project:

    • Build age is when the exact file pixi.lock locks (matched by its sha256) was uploaded to PyPI. A file PyPI does not list is freshness.unknown.
    • The newest release is the newest PyPI lists by PEP 440 that is neither a prerelease nor yanked.
    • A package from another index, a URL, git or a path is freshness.unknown, as is a name PyPI has no project for.

    pypi = false leaves PyPI packages out, as pixi-policy 0.2.0 did. archived is about conda-forge feedstocks and does not apply to PyPI. Nothing is fetched from PyPI unless one of the two limits is set.

    error[freshness.majors-behind] pytest 7.0.0: 2 major versions behind 9.1.1, the newest on PyPI, more than max-majors-behind (0)
  --> pixi.lock: environment "test", linux-64
  = help: upgrade it, or waive it while the upgrade is planned

    Caching, offline use and mirrors¶

    Answers are cached beside the extended policies: the shard index, a channel's whole repodata reduced to the newest version of each package, each PyPI project reduced to its newest release and upload times, and the feedstock lists for a day, shards for good (they are named by their content's hash). When a download fails, a stale copy stands in.

    When the data cannot be read at all, because the network is down and nothing is cached or PIXI_POLICY_OFFLINE is set with an empty cache, freshness.unavailable fails the check; build ages are still judged, since they need no data. To run offline in CI, run once online and keep PIXI_POLICY_CACHE_DIR in the CI cache.

    Repodata always comes from each package's own channel. The feedstock lists and PyPI's JSON API can come from mirrors:

    Variable Default
    PIXI_POLICY_FEEDSTOCKS_URL https://raw.githubusercontent.com/regro/cf-graph-countyfair/master/all_feedstocks.json
    PIXI_POLICY_FEEDSTOCK_OUTPUTS_URL https://raw.githubusercontent.com/conda-forge/feedstock-outputs/single-file/feedstock-outputs.json
    PIXI_POLICY_PYPI_URL https://pypi.org (/pypi/<name>/json below it)

    A waiver accepts a finding for one package, as for every rule.
